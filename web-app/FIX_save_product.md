# Окрема задача: «Зберегти виріб» нічого не робить, виріб не з'являється

Ізольована задача. Не залежить від інших наразі відкритих. Стосується лише збереження виробу та його появи в UI.

## Симптом
Користувач створює виріб у редакторі, тисне «Зберегти виріб» — і нічого не відбувається: деталі не з'являються ні в «Список усіх деталей», ні на 2D-розкрої, ні в 3D Збірці.

## Два незламні правила
1. Гейт — **тільки** `npm run typecheck` (`tsc -b`). `npx tsc --noEmit` по кореню перевіряє нуль файлів, як доказ не приймається.
2. Правити **тільки** нормальним редагуванням файлів. `node -e` з regex-замінами заборонено.

---

## Причина A: збереження не перезапускає розкрій

Файл: `src/store/slices/projectSlice.ts`

Усі мутації деталей у кінці викликають `triggerPackingAsync`, який перераховує розкрій:
- `addDetail` — рядок 213
- `addDetails` — рядок 219
- `deleteDetail` — рядок 243

А продуктові мутації цього **не** роблять — лише `set` + `finalizeProjectState`:
- `addProduct` — рядок 246
- `updateProduct` — рядок 254

Тому після збереження виробу стор оновлюється, але розкрій не перераховується → візуально «нічого».

### Фікс A
У кінці `addProduct` і `updateProduct`, після блоку `set(...)`, додати перерахунок (як у `addDetails`):
```ts
triggerPackingAsync(get().project, get().packingMode, get().parts, set, get);
```
Плюс `persist(...)`, якщо інші мутації персистять стан. Звірити точний виклик із сусідніми мутаціями в цьому ж файлі, щоб сигнатура збіглась.

---

## Причина B: UI читає сирий `project.details`, куди вироби не потрапляють

Селектор `getAllProjectDetails` (у `src/store/projectHelpers.ts:200`) об'єднує сироти `project.details` з розгорнутими `project.products`. Але під'єднаний він лише в `packingSlice`. Решта UI читає `project.details` напряму й тому виробів не бачить:

- `src/components/ui/ListsPanel.tsx` — рядки 102–114 («Список усіх деталей» → «Деталей ще немає»)
- `src/components/2d/SlabBoard.tsx` — рядки 371, 926 (пошук `part.detailId` у `project.details`)
- `src/components/3d/Viewer3D.tsx` — рядки 885, 1214–1215 (3D Збірка)
- `src/components/ui/FormsPanel.tsx` — рядки 168, 177
- `src/components/ui/TextureLayoutPanel.tsx` — рядок 112

### Фікс B
Усюди, де ці компоненти читають `project.details` для **відображення або пошуку деталі**, замінити на `getAllProjectDetails(project)`.
- Для пошуку по `detailId` (наприклад `SlabBoard`: `project.details.find(d => d.id === part.detailId)`) — побудувати `Map` з результату селектора один раз через `useMemo` і шукати в ньому.
- Імпорт: `import { getAllProjectDetails } from '../../store/projectHelpers';` (шлях звірити відносно файлу).

Примітка по `Viewer3D`: за задумом він мав рендерити з `project.products` через `ProductElement3DNode`. Якщо повний перехід зараз завеликий — мінімум переведи на `getAllProjectDetails`, щоб виріб було видно, і зафіксуй повний перехід окремою задачею (не змішувати з цим фіксом).

## Критерій приймання
1. `npm run typecheck` — код 0, порожній вивід.
2. `npm run dev`, консоль браузера чиста.
3. Наскрізь руками: створити виріб (стільниця + бортик + нога) → «Зберегти виріб» → виріб **одразу** з'являється:
   - у «Список усіх деталей» (усі деталі, включно з бортиком і ногою);
   - на 2D-розкрої (деталі лягли на сляб);
   - у 3D Збірці.

## Звіт
- `git diff` по `projectSlice.ts` і кожному зміненому компоненту;
- вивід `npm run typecheck`;
- скріншот застосунку після збереження (видно виріб у списку + на розкрої) і скріншот чистої консолі.

Без скріншота застосунку задача не зараховується — компіляція і тести вже одного разу давали хибний зелений.
